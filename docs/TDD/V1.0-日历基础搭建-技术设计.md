| 目标 | 度量 |
| --- | --- |

## 3. 关键设计决策

| # | 决策 | 结论 | 理由 | 备选方案 |
| --- | --- | --- | --- | --- |
| D1 | **SDK 内部是否使用 Element Plus** | **不使用**，SDK 自研轻量组件 + 自身 CSS | Element Plus 依赖 `:root` CSS 变量与全局样式注入，与 Shadow DOM 隔离目标冲突，且体积大；SDK 需嵌入任意系统 | 若强需求，可将 Element Plus 样式注入 Shadow Root 并重设变量，但会增大体积与耦合 |
| D2 | SDK 封装形态 | Vue 3 `defineCustomElement` 编译为 **Web Component** | 一套代码同时产出原生 Custom Element 与 Vue 封装，框架无关 | 纯手写 Web Component（开发效率低） |
| D3 | **风险等级（红黄绿）在哪算** | **后端计算**并随接口返回 | 规则集中、版本可控、前端各宿主表现一致 | 前端计算（规则分散、易不一致） |
| D4 | 币种订阅存储 | 前端 `localStorage`；宿主集成时可透传 | 符合 Q5 决策（无需登录） | 后端用户维度（V2.0 登录后） |
| D5 | 大促数据来源 | 配置文件 / 数据库，由后端下发 | 便于运营维护，避免前端硬编码 | 前端硬编码 |
| D6 | 公共假期来源 | 第三方 API 拉取作**草稿**，人工审核后生效 | 兼顾效率与准确性（Q1 决策） | 纯人工录入 |
| D7 | 独立页面与 SDK 关系 | 独立页面 = 宿主壳 + SDK | 一套逻辑两处复用，避免分叉 | 独立页面单独实现 |
| D8 | SDK 数据请求 | 原生 `fetch` 封装，不引入 axios | 减小体积 | axios（体积 ↑） |

`【待确认】` D1 是本次设计的核心取舍点，建议先做一个 **Shadow DOM + Element Plus PoC** 验证后再定稿（见第 11 章风险 R2）。

## 4. 前端技术设计

### 4.1 工程结构（pnpm workspace）

```
financial-calendar/
├── packages/
│   ├── core/            # 无框架依赖：类型定义、API client、风险色映射、i18n 文案
│   ├── sdk/             # Web Component 封装（Vue3 defineCustomElement）
│   └── vue/             # Vue3 组件封装（给 EOS 用，内部包 custom element）
├── apps/
│   ├── web/             # 独立访问页面（宿主壳，Vue3 + Element Plus）
│   └── demo-host/       # 集成示例（空白 HTML 引入 CDN 版 SDK）
├── pnpm-workspace.yaml
└── package.json
```

- `core`：纯 TS，可被 SDK / 独立页面 / 单测复用。
- `sdk`：唯一对外发布物（含 UMD、ESM、Vue 封装）。
- `web`：只负责页头、说明、容器，业务能力全部来自 SDK。

### 4.2 SDK 设计

**对外契约**

| 类型 | 名称 | 说明 |
| --- | --- | --- |
| 标签 | `<financial-calendar>` | 主视图 |
| 标签 | `<financial-calendar-widget>` | 倒计时 Widget |
| Attribute | `currencies` | 逗号分隔币种，如 `USD,EUR,CNY` |
| Attribute | `locale` | 语言，默认 `zh-CN` |
| Attribute | `month` | 初始月份，`YYYY-MM` |
| Attribute | `api-base` | 后端地址 |
| Attribute | `mode` | `full` / `readonly` |
| Attribute | `theme` | 主题标识（可选） |
| Property | `options` | 复杂配置对象（对象类型走 property 传） |
| Event | `fc:date-select` | 选择某日，payload 含 date/riskLevel |
| Event | `fc:promotion-click` | 点击大促 |
| Event | `fc:currency-change` | 订阅币种变更 |
| Event | `fc:track` | 埋点事件（宿主可接管上报） |

**技术要点**

1. **样式隔离**：`defineCustomElement` 默认启用 Shadow DOM；将组件 CSS 以 `?inline` 方式引入并在 `styles` 选项中注入 Shadow Root，避免污染宿主。
2. **局部暴露样式接口**：关键部位用 `::part()` 暴露（如 `::part(header)`、`::part(day-cell)`），主题变量用 `--fc-*` CSS 变量，宿主可在 `:host` 覆盖。
3. **属性/事件通信**：Attribute 只传字符串；对象类配置通过 Property 赋值；对外事件统一用 `CustomEvent`，事件名前缀 `fc:` 防冲突。
4. **体积控制**：`core` + `sdk` 不引入 Element Plus、axios、lodash 等，打包后 gzip < 200KB（含 Vue runtime 约 30KB+）。
5. **Vue 配置注意**：SFC 需以 custom element 模式编译（Vite 中按文件名后缀或 `compilerOptions.isCustomElement` 配置）；`web` / EOS 侧需在 Vue 配置中声明 `isCustomElement` 忽略该标签警告。
6. **兼容兜底**：目标浏览器均支持 Custom Elements v1 与 Shadow DOM；若需支持极老内核，提供 `shadowRoot:false` 降级开关（样式隔离能力下降）。

**数据流**

```
属性变更 / 挂载
   → core.apiClient 请求 /calendar/month
   → 后端返回每日 riskLevel + impacts + promotions
   → SDK 渲染日历（状态色 + 大促标识）
   → 用户交互（选日/筛选）→ 触发 CustomEvent 给宿主
```

### 4.4 状态与数据层

- 状态管理：SDK 内部用轻量 `reactive` 状态（不引入 Pinia）；独立页面可用 Pinia 管理宿主级状态。
- 请求层：`core/apiClient` 封装 `fetch`，统一处理超时、重试（1 次）、错误码、traceId。
- 缓存：
  - 内存缓存：按 `year+month+currencies+locale` 缓存月数据，避免切换月份重复请求。
  - 持久缓存：`localStorage` 存订阅币种；可选 `sessionStorage` 存字典（币种列表）。
- 降级：接口失败时展示错误态 + 重试，不用本地假数据兜底。

### 4.5 EOS 集成方式

```
EOS（Vue3 + Vite + Element Plus）
  ① npm 安装 @your-scope/financial-calendar-vue
  ② 全局注册组件 <FinancialCalendar :currencies="..." />
  ③ 通过 props 传参、@fc-date-select 监听事件
```

- `packages/vue` 内部对 custom element 做一层 Vue 包装，提供类型化 props / emits。
- 若 EOS 希望零依赖接入，也可直接走 CDN `<script>` + 原生标签。

### 4.6 i18n 与埋点

- i18n：V1.0 仅中文，但文案全部抽离为 key-value 语言包（`core/locales/zh-CN.ts`），运行时 `t(key)`，为 V1.1 多语言预留。
- 埋点：SDK 内部产出 `fc:track` 事件（事件名 + 参数），默认不发送；宿主（独立页面 / EOS）决定上报到何处，避免 SDK 强绑定埋点后端。

### 5.3 核心领域逻辑：风险等级计算

**输入**：日期 D + 关注币种集合 C（未传则取全部启用币种）+ 语言
**输出**：D 的 `riskLevel` 与影响明细

**算法（与 PRD 8.1 一致）**

```
1. 取 D 当天所有 CONFIRMED 假期 → 关联的 impact 集合 I
2. affected = { c ∈ C | ∃ impact ∈ I 且 impact.currency = c }
3. 无任何数据覆盖 D → GRAY
4. affected 为空            → GREEN
5. affected == C（全部）     → RED
6. 若 USD ∈ affected 且 max(delay_days of USD) ≥ 2 → RED
7. 其余                     → YELLOW
```

- 规则以**策略类**实现（`RiskLevelStrategy`），便于后续调整阈值而不影响其它逻辑。
- 周末不参与风险判定，仅作为日历展示的背景标记（PRD Q2 决策）。
- 计算在后端完成（决策 D3），前端只做渲染。

### 5.5 缓存设计

| 缓存项 | Key | TTL | 失效策略 |
| --- | --- | --- | --- |
| 月视图 | `fc:cal:{yyyyMM}:{hash(currencies)}:{locale}` | 12h | 管理端写操作后按前缀 `fc:cal:` 清除 |
| 日详情 | `fc:day:{yyyy-MM-dd}:{hash(currencies)}:{locale}` | 12h | 同上 |
| 币种/地区字典 | `fc:dict:currencies` / `fc:dict:regions` | 24h | 字典变更时清除 |
| 大促 | `fc:promo:{year}` | 24h | 大促变更时清除 |
| 限流计数 | `fc:rl:{ip}:{path}` | 1min | 自然过期 |

- Key 中的 `currencies` 需**排序后 hash**，避免同一集合不同顺序产生重复缓存。
- 缓存穿透：空结果也缓存（短 TTL 5min）。

### 5.6 定时任务与数据同步

| 任务 | 频率 | 说明 |
| --- | --- | --- |
| 次年公共假期同步 | 每年 10 月 1 日 03:00 | 调第三方 API，写入 `source=API`、`review_status=DRAFT` |
| 大促日期校验 | 每日 02:00 | 检查 `repeat_rule=YEARLY/ISLAMIC` 的大促是否需滚动到当年 |
| 缓存预热（可选） | 每日 06:00 | 预热热门币种组合的月数据 |

- 同步采用**适配器模式**：`HolidayProvider` 接口 + `NagerDateProvider` / `CalendarificProvider` 实现，便于替换或新增数据源（PRD 附录 B）。
- 同步结果写 `fc_sync_log`，失败告警。
- **同步数据一律为草稿**，需人工审核为 `CONFIRMED` 后才参与风险计算（保证准确性兜底）。

### 5.7 安全与限流

- V1.0 读接口**免登录**（Q5 决策），但需：
  - 按 IP + 路径限流（Redis + 令牌桶/滑窗），防刷。
  - CORS 白名单（允许 EOS 域、独立页面域、SDK 宿主域）；`【待确认】` 第三方宿主是否需动态白名单。
  - 参数校验（日期格式、币种白名单、月范围限制，如仅允许 ±2 年）。
- Admin 接口：`【待确认】` 接入方式（EOS 内部 Token / 网关注入），V1.0 至少需内网访问限制。
- 输出安全：`message_template` 渲染需转义，防 XSS。

## 7. 非功能实现方案
